# PLC 수신·CSV 재생·로그

2026-10-15 기준. 실제 서버 요청이나 PLC 제어 명령을 자동 전송하지 않는다.

## 메뉴

- SC 호기 입력/수정: `300`~`399`의 ASCII 숫자 세 자리. 앱 재실행 후 유지.
- 로그 자동 저장 폴더 선택: 처음 한 번 로컬 폴더를 지정하면 이후 수신부터 자동 누적.
- PLC CSV 재생 테스트: 장비 없이 CSV를 선택하여 시간 간격대로 재생.
- USB 통신 속도: 장치 목록 화면에서 baud rate 선택.
- USB 장치 새로고침: 연결한 장치 목록 다시 조회.
- 화면 지우기: USB 터미널 표시 내용만 지움. 로그 파일은 삭제하지 않음.

예제 채우기, 1,000건 버튼, 직접 문자열 입력창, ZIP 내보내기는 없다.
HEX, 줄바꿈, 제어선, 흐름 제어, BREAK, 알림 설정 메뉴는 화면에서 숨겼다. 기존 통신 구현은 보존했으며 현재 기본 흐름 제어는 NONE이다.

## 실제 USB

USB 시리얼 장치 연결 → 장치 목록에서 선택 → USB 접근 허용 → 터미널 수신.

baud rate는 통신 속도이며 상대 장비와 일치해야 한다. 8-N-1은 데이터 8비트, 패리티 없음, 정지 비트 1의 전송 규칙이다. 현재 이 규칙은 고정이다.
지원 USB 시리얼 드라이버와 현장 장비의 통신 조건을 확인해야 한다. 실제 PLC 연결은 미검증이다.

## PLC 원문 CSV

선택한 폴더에 한국 날짜 기준으로 다음 파일이 자동 생성된다.

```text
usb-plc-2026-10-15-000000.csv          실제 USB의 시간·원문
usb-state-readable-2026-10-15-000000.txt        실제 상태 판단·상태 변화·작업 패턴·진단
simulation-plc-2026-10-15-000000.csv   CSV 재생 중 관찰한 시간·원문
simulation-state-readable-2026-10-15-000000.txt CSV 재생의 상태 판단·상태 변화·작업 패턴·진단
```

PLC 파일은 UTF-8 CSV이며 열은 정확히 두 개다.

```csv
timestamp,message
2026-10-15T10:00:00.000+09:00,B012343000
2026-10-15T10:00:00.100+09:00,F012343000
```

한 행은 수신 콜백 한 건이다. 잡음과 분할·연속 메시지도 받은 텍스트 그대로 기록하며 정상 메시지만 추려 저장하지 않는다.
원문에 쉼표, 따옴표, 줄바꿈이 있으면 CSV 따옴표 규칙으로 보존한다. 따라서 한 레코드가 파일의 여러 줄을 차지할 수 있다.
입력은 현재 분석 대상인 ASCII 텍스트 PLC 프로토콜을 전제로 UTF-8로 해석한다. 잘못된 UTF-8 바이트는 대체 문자로 보일 수 있어 바이너리 바이트를 무손실 보관하는 형식은 아니다.

날짜는 Asia/Seoul, 시각은 앱 수신 시점이다. PLC 발생 시각은 아니다.
약 5MiB마다 같은 날짜의 다음 번호 파일로 분할한다. 날짜가 바뀌면 새 날짜 파일을 만들고 재실행 시 기존 파일에 이어 쓴다. 각 CSV 분할 파일에는 헤더가 있다.
과거 파일을 자동 삭제하지 않으므로 저장 공간을 관리해야 한다.

폴더를 선택하지 않아도 앱 내부 files/plc-logs와 files/plc-logs/simulation에 자동 기록한다. 내부 상태 파일은 .log, 선택 폴더의 상태 파일은 -state-readable- 이름의 .txt이며 내용은 같은 일반 텍스트다. 이전 JSON 형식의 상태 파일은 보존하며 새 파일과 섞지 않는다.
폴더 지정 후의 데이터부터 해당 폴더에도 기록한다. 과거 내부 기록의 자동 복사는 하지 않는다.

## CSV 재생

1. SC 호기를 설정한다.
2. PLC CSV 재생 테스트 → CSV 파일 선택.
3. 파일 검증이 끝나면 재생 시작.
4. 첫 레코드는 즉시, 이후는 첫 레코드와의 상대 시간 차이대로 전달한다.
5. 재생 중지 또는 화면을 나가면 이후 주입을 취소한다.

지원 형식은 위의 timestamp,message이며 UTF-8 BOM도 허용한다. 시간은 밀리초와 시간대가 포함된 ISO 형식(+09:00 또는 Z)이어야 한다. 같은 시각은 허용하고 시간이 역행하면 거부한다. 잘못된 열 수, 날짜, 따옴표는 오류 위치와 함께 거부한다.
최대 100,000개 레코드, 내용 합계 16MiB, 필드 하나 1MiB까지 읽는다.
쉼표·따옴표·줄바꿈을 포함한 원문도 재생한다. 이 앱이 기록한 PLC CSV를 그대로 선택할 수 있다.

CSV 원본 시각은 재생 간격 계산에 사용한다. 새 simulation 로그의 시각은 실제 재생 수신 시각이다. 원본 CSV는 변경하지 않는다.
참고 파일: examples/plc-pickup-dropoff.csv.

## 상태 판단

[A/B/E/F][숫자 5자리][3000] 형식 가정으로 조립·검증한다. 위치 단위와 3000의 의미는 미확정이다.
첫 정상 상태는 [초기 상태], 이후 Prefix 변경은 [상태 변경]으로 표시한다. 같은 Prefix의 반복 및 숫자만 변한 데이터는 상태 로그를 추가하지 않는다. SC 번호 미설정도 표시하여 상태 변화 자체는 확인할 수 있다.

상태명:

- A: Laden·컨테이너 있음·호이스트 동작
- B: Idle·컨테이너 없음·호이스트 동작
- E: Twist Lock·트위스트 잠금
- F: Twist Unlock·트위스트 해제

관찰 순서에 따른 작업 패턴:

- B→F: 픽업 진행 패턴 추정(해제 단계)
- B→F→E: 픽업 진행 패턴 추정(잠금 단계)
- B→F→E→A: 컨테이너 픽업 완료 패턴 추정
- A→E: 하차 진행 패턴 추정(잠금 단계)
- A→E→F: 하차 진행 패턴 추정(해제 단계)
- A→E→F→B: 컨테이너 하차 완료 패턴 추정
- 나머지: 픽업·하차 패턴 미확정

예시:

```text
USB | 2026-10-16T10:00:00.000+09:00 | SC 301
[상태 변경]
A(Laden·컨테이너 O·호이스트 동작)→ E(Twist Lock)
컨테이너 하차 진행 패턴 추정 (잠금 단계)
관찰 순서: A→E

```

픽업·하차는 순서에 따른 추정이다. A→E 하나로 하강을 확정하지 않으며 잠금 완료 여부, 상승·하강 방향과 컨테이너 접지도 확정하지 않는다. 중간에서 접속하여 F→E→A만 관찰한 경우 픽업 완료로 표시하지 않는다.
상태 화면과 Logcat에는 읽기 쉬운 상태 변화만 표시한다. 상태 파일에는 같은 문구와 잡음 수, 세션·호기 변경, 대기열 누락 진단도 기록한다. 원문 숫자는 PLC CSV에 보존하며 상태 설명에는 표시하지 않는다. HTTP 요청이나 JSON 요청 본문은 출력하지 않는다.
Logcat 필터는 tag:PlcMock이다.

USB 수신 화면에서도 원문과 함께 상태 변화 로그를 표시한다. `SerialService`가 기존 `PlcCaptureLog`의 분석 결과를 `SerialListener.onPlcLog`로 전달하고, `TerminalFragment`가 상태 글자색과 줄바꿈으로 구분한다. 분석 규칙과 로그 문구는 CSV 재생과 같은 `PlcStateMonitor`를 사용한다. 화면이 분리된 동안의 결과는 기존 서비스 대기열에 보관하고 화면 재연결 시 전달한다. 분석은 비동기로 처리하므로 원문 한 행마다 바로 뒤에 붙는 형태를 보장하지는 않는다.

## 모듈 경계

아래 추가 기능 파일은 `app/src/main/java/de/kai_morich/simple_usb_terminal/plc/`에 위치한다. SerialSocket과 SerialService는 기존 상위 패키지에 남아 있다. 전체 트리는 [프로젝트 구조 안내](../PROJECT_STRUCTURE.md)를 참고한다.

| 파일 | 역할 |
|---|---|
| SerialSocket / SerialService | 실제 USB 수신과 연결 유지 |
| PlcCsv | 시간·원문 CSV 읽기/쓰기 및 형식 검증 |
| CsvReplay | 원본 상대 시간에 따른 예약·재생·중지. Android에 의존하지 않음 |
| PlcTestFragment | CSV 선택 및 재생 화면 |
| PlcStateMonitor | 메시지 조립 및 상태 변경·작업 추정 |
| PlcCaptureLog | 동일 수신 경로의 분석 호출, 기록 대기열, 날짜별 파일 누적 |
| PlcLogFolder | 사용자가 지정한 Android 폴더의 파일 접근 |
| ScSettings / ScNumber | 호기 저장·입력과 형식 검증 |

USB와 CSV 재생은 PlcCaptureLog → PlcStateMonitor 경로를 공통 사용한다.

## 제한과 검사

- 정상 형식의 잡음을 진짜 데이터와 구별하지 못하며 디바운스는 없다.
- 대기열은 256개로 제한한다. 초과 시 경고하고 이후 GAP 위치에서 메시지 조립과 기준 상태를 초기화한다.
- 선택 폴더 쓰기에 실패하면 경고하며 내부 기록은 유지한다. 전원 차단에 대한 디스크 동기화 보장은 없다.
- 실제 USB 터미널의 대량 표시·백그라운드 UI 버퍼와 실제 PLC 최대 처리량은 별도 검증 대상이다.
- tests/plc/PlcCsvTest.java: CSV 원문 보존, BOM, 오류, 상대 시각 재생, 취소, 같은 시각 1,000개, 작업 추정.
- tests/plc/PlcCaptureLogTest.java: 원문/상태 분리, CSV 재사용, 자동 폴더 기록, 자정, 파일 분할, 재실행, 누락 위치.
- tests/plc/PlcStateMonitorTest.java: 분할·연속 수신, 반복 억제, 잡음, SC 번호, 상태 전이.

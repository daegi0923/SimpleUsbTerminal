# PLC 수신·CSV 재생·로그

2026-10-21 기준. 실제 서버 요청이나 PLC 제어 명령을 자동 전송하지 않는다.

## 메뉴

- SC 호기 입력/수정: `300`~`399`의 ASCII 숫자 세 자리. 앱 재실행 후 유지.
- 쌓인 로그 내보내기 (CSV / LOG): 지금까지 저장된 실제 USB·재생 테스트 로그를 선택한 폴더에 복사.
- 로그 자동 저장 폴더 선택: 처음 한 번 로컬 폴더를 지정하면 이후 수신부터 자동 누적.
- PLC CSV 재생 테스트: 장비 없이 CSV를 선택하여 시간 간격대로 재생.
- USB 수신 화면: 실제 USB 수신·연결 상태 화면으로 복귀.
- USB 장치 / 통신 속도: 여러 장치/포트 중 수신 대상을 선택. 속도를 바꾸려면 baud rate 선택 후 장치를 눌러 적용.
- USB 다시 연결: 거부한 USB 권한 또는 중지한 자동 연결을 명시적으로 재시도.
- USB 자동 연결 중지: 연결·자동 재시도를 중지. 화면을 다시 열어도 자동으로 재개하지 않음.
- USB 장치 새로고침: 연결한 장치 목록 다시 조회.
- 화면 지우기: USB 터미널 표시 내용만 지움. 로그 파일은 삭제하지 않음.

예제 채우기, 1,000건 버튼, 직접 문자열 입력창, ZIP 내보내기는 없다.
HEX, 줄바꿈, 제어선, 흐름 제어, BREAK, 알림 설정 메뉴는 화면에서 숨겼다. 기존 통신 구현은 보존했으며 현재 기본 흐름 제어는 NONE이다.

## 실제 USB

앱을 실행하면 USB 수신 화면과 상시 알림 서비스가 시작된다. 연결된 지원 USB 시리얼 포트가 하나이면 장치 선택 없이 연결한다. USB 연결·분리 알림을 받고, 2초 간격으로 상태를 확인한다. 연결 오류는 2초 후 재시도한다. 지원 장치가 없으면 대기하다가 연결 시 다시 찾는다.

최초 연결의 기본 속도는 19200 baud, 8-N-1이다. 수동 선택한 장치의 VID/PID·포트와 통신 속도는 저장하며, 이후에는 해당 장치를 우선 연결한다. 여러 포트가 있거나 동일 모델 장치가 여러 대여서 구별할 수 없으면 임의로 연결하지 않고 메뉴에서 선택하도록 안내한다. 같은 연결 세션에서는 수동으로 선택한 물리 장치를 유지한다.

USB 권한이 없으면 Android 접근 허용을 요청한다. 1.5부터 이 시스템 동의창만 백그라운드에서도 예외로 요청하고 우리 앱 화면은 자동으로 열지 않는다. 거부하면 같은 연결에서 반복해서 묻지 않으며 장치 분리·재연결이나 USB 다시 연결 조작으로 재요청한다. 권한을 우회하지 않는다.

홈 화면으로 이동하거나 CSV 테스트 화면을 열거나 화면을 꺼도 실제 USB 서비스와 파일 수집은 계속된다. Android 14 이상에서는 권한 전 대기를 specialUse 서비스, USB 연결 후 수신을 connectedDevice 서비스로 실행한다. USB 연결 동안에는 제한 시간을 두고 갱신하는 CPU 유지 잠금을 사용한다. Android 13 이상 알림 권한 거부 자체는 수집을 중단하지 않는다. 수동 중지는 재실행 후에도 유지되며 USB 다시 연결로 재개한다.

사용자 강제 종료나 SOTI/제조사 절전 정책까지 무력화하지는 않는다. 현장 단말은 SOTI에서 백그라운드 실행과 배터리 제한 예외를 확인한다. 부팅 후 앱 화면을 여는 설정은 SOTI 자동 실행으로 관리한다. 태블릿 화면은 앱 영역에 맞춰 늘어나며 Android 상태바·이동바를 숨기는 몰입 모드는 적용하지 않는다.

baud rate는 통신 속도이며 상대 장비와 일치해야 한다. 8-N-1은 데이터 8비트, 패리티 없음, 정지 비트 1의 전송 규칙이다. 현재 이 규칙은 고정이다.
지원 USB 시리얼 드라이버와 현장 장비의 통신 조건을 확인해야 한다. 실제 PLC 연결은 미검증이다.

## PLC 원문 CSV

선택한 폴더에 한국 날짜 기준으로 다음 파일이 자동 생성된다.

```text
usb-plc-2026-10-15-000000.csv          실제 USB의 시간·원문
usb-state-readable-2026-10-15-000000.txt        실제 상태 판단·상태 변화·작업 패턴·진단
simulation-plc-2026-10-15-000000.csv   CSV 재생 중 관찰한 시간·원문
simulation-state-readable-2026-10-15-000000.txt CSV 재생의 상태 판단·상태 변화·작업 패턴·진단
```

1.6부터 PLC 파일은 UTF-8 CSV이며 `timestamp,message,raw_hex` 세 열이다. 예전 `timestamp,message` 두 열 파일도 읽고 재생할 수 있다.

```csv
timestamp,message,raw_hex
2026-10-15T10:00:00.000+09:00,"^B033052000","02 30 33 33 30 35 32 30 30 30"
2026-10-15T10:00:00.100+09:00,"^F010494000","06 30 31 30 34 39 34 30 30 30"
```

한 행은 수신 콜백 한 건이다. 잡음과 분할·연속 메시지도 받은 바이트를 모두 기록하며 정상 메시지만 추려 저장하지 않는다.
원문에 쉼표, 따옴표, 줄바꿈이 있으면 CSV 따옴표 규칙으로 보존한다. 따라서 한 레코드가 파일의 여러 줄을 차지할 수 있다.
`message`는 읽기용 표시다. C0 제어값은 `^A`, `^B` 등으로, 0x80 이상 및 DEL은 `\xNN`으로 표시하며 CR/LF는 유지한다. 수신 데이터를 UTF-8로 문자 해석하지 않는다. `raw_hex`는 콜백의 모든 바이트를 두 자리 HEX로 보존하는 권위 있는 원문이다. 재생도 이 열이 있으면 표시 문구 대신 HEX로 복원한 바이트를 사용한다. 이전 CSV에 이미 U+FFFD(�)로 저장된 바이트는 복원할 수 없으며, 재생 시작 시 해당 제한을 로그로 안내한다.

날짜는 Asia/Seoul, 시각은 앱 수신 시점이다. PLC 발생 시각은 아니다.
약 5MiB마다 같은 날짜의 다음 번호 파일로 분할한다. 날짜가 바뀌면 새 날짜 파일을 만들고 재실행 시 기존 파일에 이어 쓴다. 각 CSV 분할 파일에는 헤더가 있다.
과거 파일을 자동 삭제하지 않으므로 저장 공간을 관리해야 한다.

폴더를 선택하지 않아도 앱 내부 files/plc-logs와 files/plc-logs/simulation에 자동 기록한다. 내부 상태 파일은 .log, 선택 폴더의 상태 파일은 -state-readable- 이름의 .txt이며 내용은 같은 일반 텍스트다. 이전 JSON 형식의 상태 파일은 보존하며 새 파일과 섞지 않는다.
폴더 지정 후의 데이터부터 해당 폴더에도 기록한다. 과거 내부 기록의 자동 복사는 하지 않는다.

## 제어값 변경 순서 기록 (1.7)

상태 로그도 UTF-8을 유지한다. 수신 제어 바이트 자체를 문자열 인코딩으로 해석하지 않고, `^B(0x02)`처럼 caret 표기와 HEX 값을 함께 기록한다. 제공된 이전 LOG는 UTF-8로 정상이며 U+FFFD가 없었지만 상태 기록 없이 DISCARD 진단 10,182건만 있었다. 이전 파서의 제어값 인식과 3000 고정 가정이 상태 생성 실패 원인이며 파일 인코딩을 CP949 등으로 바꾸는 문제는 아니다.

다음 기록부터 실제 제어값 이력은 `usb-state-changes-YYYY-MM-DD-번호.log`에 저장한다. 예전 `usb-state-...log`는 그대로 보존한다. 최초 유효 제어값은 `[초기 상태]`, 이후 실제 바이트가 달라질 때는 `[상태 변경]`으로 남긴다. 연결·호기 변경·누락 후 재동기화로 시작하는 분석 세션마다 순번 1부터 기록한다. 같은 제어값의 반복과 숫자만의 변경은 상태 이력을 늘리지 않으며 원문 CSV에는 모두 남는다. ASCII B(42)와 제어값 ^B(02)는 표시 상태가 같더라도 실제 바이트가 달라 기록하며 작업 패턴을 중복 확정하지 않는다.

각 이력에는 수신 시각, SC 번호(미설정이어도 기록), 세션 내 순번, 이전·현재 제어값의 HEX, 위치 원시값과 후행 원시값이 포함된다. 연결 경계 SESSION, 호기 변경, GAP은 이 파일에서 확인할 수 있다. DISCARD와 일반 STATUS 진단은 `usb-diagnostic-...log`로 분리해 상태 변경 기록을 덮지 않는다. simulation/에도 같은 구분을 적용한다. 기본 공용 Download 복사와 앱 삭제 후 보존은 두 종류 파일 모두 지원한다.

정의되지 않은 C0 제어값(00~1F, CR/LF 제외)은 숫자 9자리와 CR 종료까지 확인되면 의미 미확정으로 기록한다. 알려진 A/B/E/F와 구형 ASCII 샘플은 기존 분할·연속 수신 지원을 유지한다. 미확정 코드가 나오면 작업 패턴 순서를 끊고 F 등의 다른 상태로 대체하지 않는다.

`position_raw`와 `tail_raw`는 분석용 임시 이름이다. 제어값 뒤의 숫자 9자리를 앞 5자리/뒤 4자리로 나눈다. 예를 들어 ^B + 033052000은 position_raw=03305, tail_raw=2000이다. raw는 단위 환산이나 의미 해석 전의 숫자 원문이라는 뜻이다. 앞 값이 스프레더 높이로 추정될 뿐 단위·배율과 분리 기준 자체도 제조사 규격으로 확정한 것은 아니다. 뒤 값도 2000/4000/4027처럼 바뀌며 의미 미확정이다.

`PlcStateJournalTest`는 원시 코드 변경 순서, 반복 억제, 미확정 03/00, ASCII/제어값 구분, SC 번호 미설정, 재연결 시 새 기준, 진단 분리를 검증한다. 실측 CSV 재생 검사에서는 7,343개 메시지에서 상태 기록 92개가 순번 1~92로 남고 상태 이력에 DISCARD가 없음을 확인한다. 이는 기존 자료를 읽힌 테스트이며 새로운 실물 PLC 수신 검증을 대신하지 않는다.

## 바이너리 수신 보존과 실제 프레임 (1.6)

PLC 수신은 문자 인코딩이 보장된 텍스트가 아니다. 파일 자체는 UTF-8로 유지하면서 `raw_hex`에 원래 바이트를 HEX로 기록한다. 예를 들어 원본 `0A 31 35 FF 02 30 33 33 30 35 32 30 30 30 0D`는 `message`에 줄바꿈, `15\xFF^B033052000`, CR로 표시하고 HEX 열에서는 원본과 정확히 같은 바이트로 복원된다. 이 예의 FF는 테스트용이며 이전 파일의 �가 FF였다는 뜻은 아니다.

기존 같은 날짜 CSV가 두 열 형식이면 내용을 수정하지 않고 다음 번호의 새 세 열 파일을 만든다. 새 형식 파일은 재실행 후 이어 쓴다. 기본 Download 복사·내보내기는 기존 이름과 확장자를 유지한다. 사용자 지정 추가 자동 저장 폴더에는 세 열 CSV를 `usb-plc-bytes-...csv` 및 `simulation-plc-bytes-...csv` 이름으로 저장하여 기존 두 열 파일에 혼합하지 않는다.

분석기는 기존 ASCII A/B/E/F 샘플과 실제 제어값 01/02/05/06을 모두 지원한다. 제어값의 A/B/E/F 표시는 caret 표기 대응이며 물리적 의미가 새로 입증됐다는 뜻은 아니다. 위치 숫자 5자리와 가변 후행 숫자 4자리를 조립한다. 후행값을 3000으로 고정하지 않는다. 상태 변경 로그에는 위치와 후행 원시값도 남기되 단위·의미 미확정을 표시한다. 같은 상태에서 숫자만 달라진 기록은 원문 CSV에 계속 남고 상태 변경 문구는 반복하지 않는다.

관측된 04(^D)는 미확정 상태로 기록하고 기존 작업 패턴 순서를 끊는다. F 등 다른 의미로 대체하지 않는다. 기존 로그의 제어값과 숫자는 분석할 수 있지만 � 구간의 원래 바이트를 새로 알아낼 수는 없다. 통신 속도·8-N-1 설정은 임의로 변경하지 않았다.

실제 2026-10-26 CSV의 수신 조각 10,666개에서 메시지 7,343개와 상태 기록 92개를 확인했다. 테스트는 0x00~FF 전 바이트 CSV/재생 왕복, 제어 프레임의 모든 분할 위치, 후행값 변경, 미확정 D 처리, 기존 CSV 보존 및 새 형식 이어쓰기를 검사한다. 실측 파일은 테스트 픽스처로 앱에 포함하지 않는다.

## 다른 앱의 작업을 방해하지 않는 실행 (1.5)

USB 연결 시 Activity를 자동 실행하던 intent-filter와 장치 필터 리소스를 제거했다. 앱이 실행 중인 동안 서비스의 USB 연결/분리 수신 및 2,000ms 감시는 그대로 유지하므로, 이미 권한이 있는 장치는 화면을 띄우지 않고 재연결한다. 업데이트 후 앱을 한 번 실행하거나 MDM에서 서비스를 사용하는 상태로 시작해야 한다. 앱이 완전히 종료된 상태에서 USB를 꽂는 동작으로 화면이나 수집 서비스를 새로 시작하지 않는다.

사용자가 예외로 허용한 Android USB 사용 동의창은 필요할 때 서비스에서 요청한다. 이때 우리 Activity를 열지 않는다. 권한 요청이 진행 중이면 중복 요청하지 않고, 거부 후에는 같은 연결에서 재차 요구하지 않는다. 물리적 분리·재연결 또는 ‘USB 다시 연결’ 조작은 새 요청을 허용한다. 권한이 허용되기 전에는 데이터 수신을 시작할 수 없다.

알림 권한을 실행 중 자동으로 요청하지 않는다. 사용자가 수신 화면 메뉴의 ‘상주 알림 표시 설정’을 직접 눌렀을 때만 요청한다. SC 설정·파일 내보내기 등 직접 실행한 메뉴의 창은 유지한다. 전경 서비스 유지에 필요한 상주 알림은 새 조용한 채널(`.Channel.Quiet`, IMPORTANCE_LOW)에서 소리·진동 없이 표시한다. Android 7 이하도 낮은 우선순위와 silent 설정을 사용한다. 알림 문구는 고정하고, 상태 변경마다 배너·전체화면 알림을 띄우지 않는다. 기존 알림 채널을 사용자가 높게 설정해 둔 경우의 영향을 피하기 위해 새 채널을 사용한다. 새 채널 설정도 이후 사용자나 MDM이 변경할 수 있다.

연결 대기·연결 실패·분리·재연결·권한 관련 상태가 바뀌면 `UsbStatus` Logcat과 `usb-state-...log`의 `[STATUS]` 항목에 기록한다. 동일한 상태를 반복 저장하지 않는다. 이 진단 기록은 PLC 메시지 조립을 초기화하지 않고 원문 CSV에도 섞지 않는다. 기존 내부 원본 및 공용 Download 자동 복사 경로는 그대로 유지한다.

`QuietRuntimeInstrumentation`은 실제 서비스에 I/O 오류를 4회 주입하고 지속 로그와 조용한 알림 설정을 검사한다. `build/verification/quiet-runtime-check.py`는 설정 앱을 앞에 둔 상태에서 화면 초점이 유지되는지, 수동 메뉴·권한 요청은 가능한지와 공용 로그 복사를 확인한다. 실제 물리 USB 분리·재연결과 제조사 시스템창은 별도 실기기 확인 대상이다.

## 기본 공용 로그 자동 저장 (1.4)

Android 10(API 29) 이상에서는 폴더 선택이나 저장소 전체 접근 권한 없이 내부 원본을 `Download/SC-Log-Miner/<설치 식별자>/`에 자동 복제한다. PC USB 탐색기에서는 `내장 저장공간 → Download → SC-Log-Miner`로 확인한다. 실제 USB 파일은 설치 폴더 바로 아래, 테스트 로그는 `simulation/` 아래에 원래 `.csv`·`.log` 이름과 내용으로 저장한다. 기록이 한 건도 없으면 파일과 폴더가 아직 생성되지 않을 수 있다.

업데이트 후 첫 실행에서 과거 내부 CSV/LOG 전체를 복사하고, 이후에는 변경된 파일의 누락된 바이트만 복사한다. 내부 기록과 별도 작업 스레드에서 보통 250ms 단위로 요청을 묶는다. 파일 복사 중에도 수신과 내부 기록은 계속된다. 실패하면 내부 원본을 유지하고 5초 뒤 전체 파일을 재확인한다. 사용자 지정 ‘로그 자동 저장 폴더’는 추가 저장 대상으로 계속 사용하며, 그 폴더의 오류 때문에 기본 공용 복사가 생략되지 않는다.

수신 화면 상단에는 복사 중, 공용 저장 완료, 저장 실패를 표시한다. 앱을 삭제해야 한다면 먼저 `USB 자동 연결 중지`로 수신을 멈춘 뒤 `공용 로그 자동 저장 완료`를 확인한다. 복사가 끝나기 전에 강제 종료하거나 삭제하면 아직 공용으로 복사되지 않은 마지막 기록은 남지 않을 수 있다. 대량의 과거 로그가 있으면 최초 복사에 시간이 더 걸린다.

공용 파일은 앱 삭제 후에도 남는다. 재설치 시 새로운 설치 폴더를 사용해 이전 설치의 로그를 덮어쓰지 않는다. 같은 설치의 재실행은 저장된 URI와 공용 파일의 실제 길이를 확인하여 이어 쓴다. 공개 파일이 원본보다 길면 기존 파일을 보존하고 새 파일을 만든다. 복사 후 사용자가 같은 길이로 수정한 내용까지 검증하는 동기화 기능은 아니다.

사진의 `Android/data/<패키지>/`는 앱 전용 외부 저장소이며 앱 삭제 시 함께 삭제되는 영역이다. 로그 보존용 공용 폴더로 사용하지 않는다. Android 5~9에서는 기존 내부 저장을 유지하고, 공용 저장이 필요하면 기존 ‘로그 자동 저장 폴더 선택’을 설정한다. 기본 자동 Download 저장은 Android 10 이상에서만 동작한다.

참고: [Android 공용 저장소와 MediaStore](https://developer.android.com/training/data-storage/shared/media), [앱 전용 저장소의 삭제 동작](https://developer.android.com/training/data-storage/app-specific).

## 쌓인 로그 내보내기

상단 메뉴 → 쌓인 로그 내보내기 (CSV / LOG) → 파일 목록에서 체크 → 선택 파일 내보내기 → 공용 폴더 선택 → 폴더 사용 허용. 파일 목록에는 실제 USB·테스트 로그의 상대 경로와 용량을 표시하며 전체 선택·선택 해제를 지원한다. 처음에는 전체가 선택돼 있고, 선택이 없으면 내보내기 버튼은 비활성이다. 폴더 선택을 취소하면 체크 상태가 유지된다. Documents 아래의 원하는 하위 폴더 등을 선택한다. Android 11 이상에서 내부 저장소 최상위나 Download 폴더 자체를 선택할 수 없다면 그 아래에 새 하위 폴더를 만들어 선택한다.

선택한 폴더 아래에 `SC-Log-Miner-logs-yyyyMMdd-HHmmss-SSS` 폴더를 새로 만든다. 선택한 실제 USB의 `.csv`·`.log` 파일 및 `simulation/` 아래 테스트 로그를 원래 파일명·확장자·내용 그대로 복사한다. 이름이 겹치면 다른 내보내기 폴더를 사용하며 기존 내보내기와 원본은 덮어쓰거나 삭제하지 않는다. 설정 파일은 포함하지 않는다. 로그가 없으면 안내하고 빈 내보내기 폴더를 만들지 않는다.

내보내기 시작 시점에 파일에 기록된 길이를 완성된 기록 단위로 확정하고, 복사는 별도 작업 스레드에서 수행한다. USB 수신·파일 수집은 계속되며 이후에 추가된 기록은 다음 내보내기에 포함된다. 화면을 회전해도 선택 상태·진행 작업·결과가 유지된다. 완료 시 파일 수와 용량을 표시하고, 폴더 접근 또는 저장 실패는 완료로 표시하지 않는다. 실패한 내보내기 폴더에는 일부 파일이 남아 있을 수 있으나 원본은 유지된다.

1.3에서는 시스템 폴더 선택창이 없거나 기기 관리 정책으로 열 수 없을 때 앱을 종료하지 않고 안내한다. 이 경우 Android 10(API 29) 이상에서는 버튼이 `다운로드에 저장`으로 바뀐다. 사용자가 누르면 공용 `Download/SC-Log-Miner-logs-시각-고유값/`에 선택 파일을 복사한다. 저장소 전체 접근 권한은 추가하지 않으며 MediaStore Downloads로 이번 내보내기 파일만 생성한다. 복사가 모두 끝나면 파일을 공개하고, 실패하면 이번에 만든 파일만 정리를 시도한다. Android 9 이하는 시스템 파일 선택창을 사용할 수 있도록 관리자 설정이 필요하다. 기존 ‘로그 자동 저장 폴더 선택’도 선택창 실행 실패 시 안내하며 내부 기록을 계속한다.

폴더 선택 중 시스템이 앱 프로세스를 다시 만들더라도 선택한 파일 목록을 복원하며 전체 파일로 임의 변경하지 않는다. 복사 중 프로세스가 종료된 경우에는 자동 재실행하지 않고 중단 안내를 표시한다. 원본은 유지되므로 파일 목록을 다시 열어 내보낼 수 있다.

이 기능은 과거 로그의 일회성 복사다. 기존 '로그 자동 저장 폴더 선택' 설정을 바꾸지 않으며, 이후 수신의 자동 저장 위치와는 독립적이다. 앱 삭제 시 내부 원본은 삭제되지만 공용 폴더로 내보낸 파일은 남는다.

## CSV 재생

1. SC 호기를 설정한다.
2. PLC CSV 재생 테스트 → CSV 파일 선택.
3. 파일 검증이 끝나면 재생 시작.
4. 첫 레코드는 즉시, 이후는 첫 레코드와의 상대 시간 차이대로 전달한다.
5. 재생 중지 또는 화면을 나가면 이후 주입을 취소한다.

지원 형식은 timestamp,message 및 timestamp,message,raw_hex이며 UTF-8 BOM도 허용한다. 시간은 밀리초와 시간대가 포함된 ISO 형식(+09:00 또는 Z)이어야 한다. 같은 시각은 허용하고 시간이 역행하면 거부한다. 잘못된 열 수, 날짜, 따옴표는 오류 위치와 함께 거부한다.
최대 100,000개 레코드, 내용 합계 16MiB, 필드 하나 1MiB까지 읽는다.
쉼표·따옴표·줄바꿈을 포함한 원문도 재생한다. 이 앱이 기록한 PLC CSV를 그대로 선택할 수 있다.

CSV 원본 시각은 재생 간격 계산에 사용한다. 새 simulation 로그의 시각은 실제 재생 수신 시각이다. 원본 CSV는 변경하지 않는다.
참고 파일: examples/plc-pickup-dropoff.csv.

## 상태 판단

기존 ASCII A/B/E/F 또는 실제 제어값 01/02/04/05/06 뒤의 숫자 9자리를 조립·검증한다. 앞 5자리 위치와 뒤 4자리 후행값은 원시값 그대로 보관한다. 위치 단위와 후행 4자리의 의미는 미확정이다.
첫 정상 상태는 [초기 상태], 이후 Prefix 변경은 [상태 변경]으로 표시한다. 같은 Prefix의 반복 및 숫자만 변한 데이터는 상태 로그를 추가하지 않는다. SC 번호 미설정도 표시하여 상태 변화 자체는 확인할 수 있다.

상태명:

- A: Laden·컨테이너 있음·호이스트 동작
- B: Idle·컨테이너 없음·호이스트 동작
- E: Twist Lock·트위스트 잠금
- F: Twist Unlock·트위스트 해제

관찰 순서에 따른 작업 패턴:

- B→F: 픽업 진행 패턴 추정(해제 단계)
- B→F→E: 픽업 진행 패턴 추정(잠금 단계)
- B→F→E→A: 컨테이너 픽업 완료 패턴 추정
- A→E: 하차 진행 패턴 추정(잠금 단계)
- A→E→F: 하차 진행 패턴 추정(해제 단계)
- A→E→F→B: 컨테이너 하차 완료 패턴 추정
- 나머지: 픽업·하차 패턴 미확정

예시:

```text
USB | 2026-10-16T10:00:00.000+09:00 | SC 301
[상태 변경]
A(Laden·컨테이너 O·호이스트 동작)→ E(Twist Lock)
컨테이너 하차 진행 패턴 추정 (잠금 단계)
관찰 순서: A→E

```

픽업·하차는 순서에 따른 추정이다. A→E 하나로 하강을 확정하지 않으며 잠금 완료 여부, 상승·하강 방향과 컨테이너 접지도 확정하지 않는다. 중간에서 접속하여 F→E→A만 관찰한 경우 픽업 완료로 표시하지 않는다.
상태 화면과 Logcat에는 읽기 쉬운 상태 변화만 표시한다. 상태 파일에는 같은 문구와 잡음 수, 세션·호기 변경, 대기열 누락 진단도 기록한다. 원문 숫자는 PLC CSV에 보존하며 상태 변경 시 원시 위치값과 후행값을 함께 표시한다. HTTP 요청이나 JSON 요청 본문은 출력하지 않는다.
Logcat 필터는 tag:PlcMock이다.

USB 수신 화면에서도 원문과 함께 상태 변화 로그를 표시한다. `SerialService`가 기존 `PlcCaptureLog`의 분석 결과를 `SerialListener.onPlcLog`로 전달하고, `TerminalFragment`가 상태 글자색과 줄바꿈으로 구분한다. 분석 규칙과 로그 문구는 CSV 재생과 같은 `PlcStateMonitor`를 사용한다. 화면이 분리된 동안의 결과는 기존 서비스 대기열에 보관하고 화면 재연결 시 전달한다. 분석은 비동기로 처리하므로 원문 한 행마다 바로 뒤에 붙는 형태를 보장하지는 않는다.

## 모듈 경계

아래 추가 기능 파일은 `app/src/main/java/de/kai_morich/simple_usb_terminal/plc/`에 위치한다. SerialSocket과 SerialService는 기존 상위 패키지에 남아 있다. 전체 트리는 [프로젝트 구조 안내](../PROJECT_STRUCTURE.md)를 참고한다.

| 파일 | 역할 |
|---|---|
| SerialSocket / SerialService | 실제 USB 수신과 연결 유지 |
| PlcCsv | 시간·원문 CSV 읽기/쓰기 및 형식 검증 |
| CsvReplay | 원본 상대 시간에 따른 예약·재생·중지. Android에 의존하지 않음 |
| PlcTestFragment | CSV 선택 및 재생 화면 |
| PlcStateMonitor | 메시지 조립 및 상태 변경·작업 추정 |
| PlcCaptureLog | 동일 수신 경로의 분석 호출, 기록 대기열, 날짜별 파일 누적 |
| PlcLogFolder | 사용자가 지정한 Android 폴더의 파일 접근 |
| ScSettings / ScNumber | 호기 저장·입력과 형식 검증 |

USB와 CSV 재생은 PlcCaptureLog → PlcStateMonitor 경로를 공통 사용한다.

## 제한과 검사

- 정상 형식의 잡음을 진짜 데이터와 구별하지 못하며 디바운스는 없다.
- 파일 기록 대기열은 256개로 제한한다. 초과 시 경고하고 이후 GAP 위치에서 메시지 조립과 기준 상태를 초기화한다.
- 선택 폴더 쓰기에 실패하면 경고하며 내부 기록은 유지한다. 전원 차단에 대한 디스크 동기화 보장은 없다.
- 화면 대기열은 256KiB/1,024건, 표시 텍스트는 30,000자 초과 시 최근 20,000자로 제한한다. 오래된 화면 항목을 생략하면 안내하며 파일 기록은 별도 경로로 계속한다. 실제 PLC 최대 처리량은 실장비 검증 대상이다.
- tests/plc/PlcCsvTest.java: CSV 원문 보존, BOM, 오류, 상대 시각 재생, 취소, 같은 시각 1,000개, 작업 추정.
- tests/plc/PlcCaptureLogTest.java: 원문/상태 분리, CSV 재사용, 자동 폴더 기록, 자정, 파일 분할, 재실행, 누락 위치.
- tests/plc/PlcStateMonitorTest.java: 분할·연속 수신, 반복 억제, 잡음, SC 번호, 상태 전이.

## 자동 연결 검사

`tests/usb/UsbAutoConnectPolicyTest.java`는 단일 장치 선택, 저장한 장치/포트, 동일 모델 수동 선택, 중복 요청 방지, 2,000ms 재시도 경계, 권한 거부·분리·재요청, 수동 중지 유지를 검증한다. `SerialUiBufferTest.java`는 표시 대기열 용량·순서·누락 안내·동시 수신을 검증한다. 실제 USB 권한 창과 물리 케이블 재연결은 대상 태블릿에서 확인한다.

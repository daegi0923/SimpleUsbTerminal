# PLC 재생 CSV

- plc-pickup-dropoff.csv: 픽업·하차 순서 검증용으로 만든 짧은 가상 데이터.
- plc-capture-approx-1s.csv: 사용자가 제공한 화면 캡처의 읽을 수 있는 시각·메시지를 옮긴 근사 재생 데이터. 31개 레코드, 약 1초 간격, 약 30초 재생.
- plc-full-cycle-approx-1s.csv: 두 화면 캡처의 반복 양상을 참고해 구성한 가상 한 사이클 데이터. 51개 레코드, 약 1초 간격, 약 50초 재생. 반복 제거 순서는 B → F → E → A → E → F → B이며 픽업·하차 완료 추정이 각각 1회, 상태 변경이 총 6회 예상된다.

한 사이클 CSV는 실제 연속 수집 로그의 전사가 아니다. 픽업 구간은 B 12회 → F 1회 → E 9회 → A 17회, 하차 구간은 E 3회 → F 5회 → B 4회로 구성했다. 시각(2026-10-16 10:00:00 +09:00 시작)과 간격은 테스트용으로 지정했고 숫자 부분은 캡처 값을 참고한 예시다. 실제 상태 지속 시간이나 거리·위치를 뜻하지 않는다.

캡처에는 날짜와 시간대가 표시되지 않아 CSV 형식을 맞추기 위해 2026-10-15와 +09:00을 임의 지정했다. 실제 수집 날짜를 뜻하지 않는다.
윗부분의 잘린 첫 행과 메시지 앞의 녹색 15 및 깨져 보이는 제어 문자 표시는 포함하지 않았다. 이미지 전사 자료이므로 원본 수신 바이트의 정확한 복원은 아니다.
숫자 부분은 거리·위치 등의 의미를 확정하지 않고 보이는 값을 메시지에 보존했다. 앱의 상태 로그는 Prefix 변경을 기준으로 한다.

근사 캡처 CSV의 반복 제거 상태 순서는 F → E → A → E → F → B이다. 최초 F는 기준 상태, 이후 상태 변경 로그는 5회가 예상된다. 마지막 A → E → F → B는 하차 추정 패턴이다. 첫 B가 잘려 없어 픽업 패턴 전체는 포함하지 않는다.

앱에서 PLC CSV 재생 테스트 → CSV 파일 선택으로 해당 파일을 열고 재생한다.

한 사이클 CSV는 앱의 `res/raw/plc_full_cycle_approx_1s.csv`에도 동일하게 내장되어 있다. PLC CSV 재생 테스트 화면에 진입하면 기본으로 준비되므로 파일 복사 없이 재생 시작을 누르면 된다. CSV 파일 선택으로 외부 파일을 재생할 수도 있다. 내장본 변경 시 앱을 다시 빌드·설치해야 한다.
